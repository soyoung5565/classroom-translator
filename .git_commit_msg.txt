feat(1.6.0): 双引擎热切换轮换 + 识别结果显示完整

## 问题 1：识别结果没显示完整（用户 2026-11-03 截图）
卡片上英文和中文都停在半句话，且断在同一个位置：
  英文 "Okay, I will get back to you. Stand up. What is"
  中文 "好的，我会回复你。站起来。什么是"

四个独立根因，全部已修：

1. **ASR 8 秒硬上限把句子切开**（数据层截断，主因）
   MAX_SEGMENT_MS=8000 把超长句切成两段，两段独立识别（不带前缀续听），
   第一段转写就停在 8 秒处 → 翻译照着半句翻 → 中英文一起断在半句。
   修法：新增 TranscriptMerger（纯逻辑，可测），识别端标记"本段被硬切开"，
   下一段到达时合并（去边界重复词）成完整句子再输出。
   上层 addOrMergeEntry 用"新文本以旧文本开头"判定续写 → 同一张卡片替换成完整句子。

2. **云端覆盖会改写并截断英文**（数据层截断）
   maybeCloudOverride 原来让云端同时回传英文，云端复述时会顺手压缩/截断，
   英文被截短后中文照着翻 → 两边一起断。
   修法：云端**只回中文**（cloudBatchTranslate 返回 List<String>），
   英文保留 ASR 原始识别结果 —— 那才是老师实际说的话，是唯一事实来源。
   解析新增 parseChineseList，兼容纯字符串/对象/旧二元组三种格式。

3. **云端覆盖按下标回填会错位**（顺带修的真 bug）
   idx = updated.size - recent.size + i：云端请求要 ~2 秒，这期间新条目不断进来
   → updated.size 变大 → 译文贴到别的句子上。
   修法：发请求前记下每段的条目 id，回来按 id 精确回填。

4. **UI 把英文硬截成 1~2 行**（显示层截断）
   MainScreen TranslationCard 英文 maxLines=1/2 + Ellipsis → 后半句变"…"被吃掉。
   修法：英文不限行数完整显示。WholeSessionScreen 的中文 maxLines=3 同样放开。

另修两个"内容丢失"源：
- cleanAsrOutput 用 `^(english|chinese|malay)\b\s*` 无条件剥开头语言名 →
  老师第一句 "English is easy to learn." 被剥成 "is easy to learn." → 凭空少一个词。
  现在只有"带冒号的语言标签"和"整个输出就是语言名"两种情况才剥。
- 不足 0.5s 的音频片段被取走却直接丢弃 → 老师开头几个字被吃掉。现在放回缓冲。

## 问题 2：时间长了卡住 / 正确率下降 / 引擎卡死
项目 2026-09-24 实测已坐实真因是**内存枯竭**（MemFree 165MB / zram swap 9.2GB），
重启 llama-server 后 MemFree 回到 2973MB、ASR 尾段延迟 22.3s→3.09s（7 倍改善）。
所以「定期换引擎」是唯一被数据验证过的解法。

按用户指定的时序实现双引擎热切换：
- 周期 5 分钟；4 分 30 秒启动备用引擎 B（端口 +100，不抢主引擎端口）
- B /health 就绪后接管 A；A 延迟 2.5s 释放（让在途请求跑完）
- 下一轮 A 变备用，循环
- B 迟迟不就绪 → **放弃本轮继续用 A**，绝不为守时把用户服务搞挂

配套修掉三个会让"轮换"变成"停摆"的坑：
- LocalVllmAsrStream 原本固定 baseUrl → 轮换后端口变了，请求全打到已下线的引擎。
  现在改成 baseUrlProvider lambda，每次请求问管理器要当前 URL。
- /health 只探端口，探不出"进程活着但推理卡死"。新增 reportAsrFailure/
  reportTransFailure：ASR/翻译连续失败 3 次 → 强制重启对应引擎。
- 引擎轮换判定抽成 EngineRotationPolicy（纯逻辑，单一真相源）。
  轮换计时**相对上一次动作**而非对齐整点 —— 之前对齐整点会导致
  上一轮放弃后下一轮准备时刻已过 → 永远轮不过来（单测抓到）。

其他：日志文件 4MB 封顶（轮换会持续 append 同一批日志）；UI 状态栏显示
当前引擎/备用引擎/下次轮换秒数；自修复的 restartServices 改为只换对外那个引擎，
不再 stop()+start()（否则会清掉已加载好的备用引擎）。
