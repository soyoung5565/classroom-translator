官方文档实测示例：`sherpa-onnx-streaming-zipformer-en-2023-06-21` → **Elapsed 0.5s, RTF 0.076**（桌面 CPU）（https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-transducer/zipformer-transducer-models.html WER**、**词发射延迟 590ms vs Amazon 920ms**、算力 0.08 core-hour vs Moonshine Medium 3.36（https://picovoice.ai/products/voice/streaming-speech-to-text ）。有 Android SDK，**无马来口音公开数据**，需商业授权。\n- **NVIDIA 2.6 Qwen3-ASR —— 准确率最强，但端侧无法真流式\n\n官方 benchmark（internal Dialog-Accented English WER 越低越好）：GPT-4o-Transcribe 28.56 / Gemini-2.5-Pro 23.85 / Doubao-ASR 20.41 / Whisper-large-v3 21.30 / Fun-ASR-MLT-Nano 19.96 / **Qwen3-ASR-0.6B 16.62** / **Qwen3-ASR-1.7B 16.07**（https://github.com/QwenLM/Qwen3-ASR 、https://arxiv.org/html/2601.21337v1 ）。\n\n**关键限制**：Qwen3-ASR fully supports streaming inference. **Currently, streaming inference is only available with the vLLM backend.**（https://huggingface.co/Qwen/Qwen3-ASR-0.6B ）端侧 llama.cpp mtmd 没有 prompt cache，只能走分块+重编码的伪流式。\n\n**本项目实测（最贴近目标场景）**：端侧引擎横向（骁龙 8 Elite，马来口音英语，12 条）：Qwen3-ASR-0.6B Q8_0 **~90.5%**、编码 RTF ~0.09（常驻）；whisper-small-int8 ~89.5%、RTF ~0.16；Fun-ASR-MLT-Nano int8 ~87.4%、**RTF ~1.07（~6s/条）**。端侧流式端到端（真实 24.8 分钟马来口音素材，内录 → 2s 窗口 flush → llama-server）：**每句延迟 avg ~0.5s / min 219ms / max ~1s，4000+ 请求 0 崩**。PC 侧 vLLM Qwen3-ASR 真实课堂视频：ASR 1.43s、翻译 2.08s、端到端 3.51s，关键词 F1 95.8%。\n\n**结论**：准确率和冷机延迟本来就达标；现在的退化是长时运行+内存压力引入的工程问题，不是选型问题。**风险点**：App 的 `asr_mode=ondevice-whisper` 会走每轮发 8 秒音频的非流式路径（真流式应为 `local_vllm` + `LocalVllmAsrStream`）——「每段 8 Android 平台侧的 2 小时风险（隐形杀手）\n\n1. **前台服务类型必须声明 `microphone`**（Android 14+ 强制）：`android:foregroundServiceType=\"microphone\"` + `FOREGROUND_SERVICE_MICROPHONE` + `FOREGROUND_SERVICE_TYPE_MICROPHONE`（https://developer.android.com/develop/background-work/services/fgs/service-types ）。\n2. **唤醒锁不要长期持有**：Android vitals 把「熄屏 + 前台服务 partial wake lock **累计 ≥2 小时/24 小时**」判为过度使用（https://android-developers.googleblog.com/2025/09/guide-to-excessive-wake-lock-usage.html ）。\n3. **HyperOS/小米额外杀进程**：小米系对前台服务也不客气。需引导用户开「电池省电→无限制」+「自启动」+「后台弹出界面」（https://stackoverflow.com/questions/57976116/xiaomi-devices-are-stopping-foreground-services ）。\n4. **麦克风中断**：来电/抢麦/媒体播放会中断采集，需监听音频焦点并自动恢复。\n5. **zram 是内存拓展的代价**：长课下它会把任何内存失控放大成延迟灾难——这正是 `--cache-ram 0` 是最高优先动作的原因。\n6. **热设计**：本次 39~42°C 说明散热不是瓶颈，但**若修好内存后 CPU 负载上升，需重测 2 小时温控曲线**。\n\n---\n\n## 5.
